# CommitQuest 0.4.0 release candidate

Prepared and production-verified August 18, 2026. The `v0.4.0` tag and GitHub Release are not yet authorized.

## Outcome

CommitQuest adds user-owned, durable campaign libraries without weakening the account-free public preview. A visitor can authenticate with GitHub, save a public-repository campaign privately, return to it, refresh it deliberately, change its stored visibility preference, export it, delete it, sign out, and permanently delete imported account data.

## Highlights

- GitHub OAuth identity with no requested scopes, one-time expiring state, S256 PKCE, immediate provider-token disposal, and rotated opaque sessions.
- Owner-scoped PostgreSQL persistence with Flyway, jOOQ, private defaults, refresh-in-place behavior, a 25-campaign limit, and transactional account deletion.
- Same-origin CSRF-protected saved-campaign APIs plus a generated Angular client.
- A responsive private campaign vault with explicit unavailable, waking, signed-out, authenticated, expired-session, export, and destructive-confirmation states.
- A branded OAuth preflight that keeps Render Free cold starts inside CommitQuest instead of exposing the infrastructure wake page.
- Fast same-account reconnect alongside an explicit GitHub-owned account picker, presented through an accessible modal.
- Zero-cost deployment on Vercel Hobby, Render Free, and Neon Free with no paid dependency.

## Deliberate limits

- Authentication does not grant private-repository access; minimum-permission GitHub App installation begins in v0.5.
- The current authenticated presentation is accepted for v0.4 but is not the v0.5 design target. Version 0.5 includes a complete signed-in redesign with shared Modern and Chronicle modes.
- Refresh remains explicit until webhook ingestion begins in v0.6.
- No public showcase route exists until v0.8.
- No billing, AI-authored state, queue, background worker, or paid resource is introduced.

## Release boundary

Completing production verification does not create or authorize a tag or GitHub Release. Those actions require a separate, explicit owner instruction.
