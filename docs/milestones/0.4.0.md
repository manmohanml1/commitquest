# Milestone 0.4.0: User-owned saved campaigns

**Status:** Complete and production verified. No tag or GitHub Release is authorized.

## Outcome

A visitor can sign in with GitHub, save an ephemeral public-repository preview as a private campaign, return to it later, refresh it deliberately, change its stored visibility preference, export its data, delete it, sign out, and delete the account's imported data.

GitHub identity proves the account owner. It does not grant repository access. Private repositories and GitHub App installation remain v0.5 work.

## Acceptance criteria

- GitHub OAuth requests no scopes and uses one-time expiring state plus S256 PKCE.
- OAuth access tokens are discarded after CommitQuest reconciles the GitHub user identity.
- The browser receives an opaque Secure, HttpOnly, SameSite session cookie and no reusable provider credential.
- Sessions are revocable, expire, rotate on sign-in, and survive a Render restart through PostgreSQL.
- Every saved-campaign operation derives the owner from the authenticated session, never a request-supplied user identifier.
- Saving the same repository refreshes the existing campaign instead of creating duplicates.
- New campaigns are private by default; v0.4 may retain an unlisted preference but exposes no public showcase route.
- A campaign snapshot records projection, mapping, scoring, and export schema versions.
- List, read, refresh, visibility, export, and delete paths cannot reveal another account's campaign.
- Account deletion revokes sessions and deletes imported campaign data transactionally.
- The bundled campaign and ephemeral public preview continue working without authentication or PostgreSQL.
- Connected behavior remains disabled unless its required database and identity configuration is complete.
- PostgreSQL migrations, adapter integration, authorization matrices, OpenAPI generation, Java architecture checks, Angular behavior, and production builds pass.

## Limits

- The v0.4 authenticated layout is an accepted functional release baseline, not the intended v0.5 design. A complete signed-in redesign with Modern and Chronicle modes is explicitly planned in the [0.5.0 milestone](0.5.0.md).
- Maximum 25 saved campaigns per account in v0.4.
- One owner and one public GitHub repository per campaign.
- No background synchronization; refresh is explicit until v0.6.
- No public showcase response; unlisted/public presentation begins in v0.8.
- No private repository access, repository writes, billing, AI-authored state, queue, or paid resource.

## Release rule

Completing this checklist does not authorize a `v0.4.0` tag or GitHub Release. The implementation, pull request, merge, connected resources, and production deployment recorded above were separately approved. A version tag or release requires a new, explicit owner instruction.
