# CommitQuest 0.3.0

Originally released August 12, 2026. The existing tag was owner-authorized for update on August 17, 2026 after final production verification.

## Outcome

CommitQuest now accepts one public GitHub repository URL and produces a temporary, evidence-aware campaign without an account, persistence, or a GitHub App installation.

## Highlights

- Java 25 and Spring Boot 4 form the sole GitHub API boundary.
- Angular consumes a generated OpenAPI client and keeps provider credentials out of the browser.
- Issues and `ROADMAP.md` items become source-linked candidate quests.
- Merged pull requests become verified encounters; sparse histories receive clearly labelled commit expeditions.
- GitHub Releases, tags, and default-branch foundations produce distinct chapter types.
- Full, history, foundation, and archive campaign modes preserve the repository's actual workflow shape.
- A clearly labelled CommitQuest recommendation keeps repositories without issues or roadmap entries actionable.
- Bounded provider reads and a ten-minute in-memory cache require no database or paid service.

## Verification

- Schema version: `3`
- Mapping algorithm version: `6`
- All API, architecture, OpenAPI, Angular, lint, formatting, security, and production-build gates passed.
- All 17 public repositories owned by `manmohanml1` passed the hosted compatibility audit.
- Production serves the same campaign response through Render and the Vercel same-origin proxy.
- The hosted stack remains one Render Free API service and one Vercel Hobby static application.

## Known operational behavior

Render Free sleeps during inactivity, so the first preview commonly takes approximately 30–60 seconds while the service wakes and can exceed two minutes. Warm and cached previews remain substantially faster. No keep-alive or payable infrastructure is used.
